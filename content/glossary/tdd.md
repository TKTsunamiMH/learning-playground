## In short
TDD is writing a failing test first, then writing the minimal code to make it pass, then refactoring—the Red-Green-Refactor cycle.

## What it means for a .NET Full Stack developer
TDD helps clarify requirements before you code and keeps API or service design focused on behavior.  
It encourages small, incremental changes with immediate feedback. Tests exist by default (not postponed).  
Many teams use practical TDD for complex business logic rather than strict TDD for every line.  
The cycle: (1) write failing test (Red), (2) write minimal code (Green), (3) clean up (Refactor).

## Example
Scenario: Write a failing test for an order discount rule, write the rule just enough to pass, then refactor.
